2. Architecture & Technology Stack

2.1 System Architecture Overview [max 200 words]

The user works in a React single-page app (built with Vite). It calls a Python FastAPI backend over HTTPS; both are served from one Replit autoscale deployment. A CV upload is read on the server with pypdf or a built-in Word reader; personal data (name, email, phone, IC number, age, gender) is removed before any matching. Only for photos or complex layouts, and only when a key is configured, the redacted content is sent to the Google Gemini API, which returns phrases in a fixed JSON schema; every phrase is checked against the CV's own text. Matched skills go to three models that run inside the backend: Model 1 (AI-exposure classifier trained on O*NET tasks, stored as JSON), Model 2 (damped trend forecast on monthly arXiv paper counts, refreshable from the arXiv API) and Model 3 (exact scoring of the Catch the AI exercise). The scoring engine combines them with WEF, DOSM and MyCOL job-market figures into an Edge Score with a low–high range for two scenarios, then builds an ordered pathway from a catalog of 53 checked learning resources. Catalogs are JSON files in the repository; no database and no user data are stored.

Browser (React) ──► FastAPI (Replit deployment) ──► Model 1 · Model 2 · Model 3 ──► Edge Score + pathway │ ▲ ├─(optional, redacted)─► Gemini API └── arXiv API (trend refresh) └─ JSON catalogs in repo: skills, roles, SDGs, courses, WEF / DOSM / MyCOL figures

6. Security, Privacy & Responsible Use

6.1 Data Handling & Privacy [max 150 words]

The app collects only what the user uploads: a CV file or pasted text, skill levels, a goal role and Catch the AI answers. The CV is read in memory once and is not saved; no database, account or tracking of personal data exists. Before matching, the name line, email, phone, IC number, age, date of birth and gender are removed, so matching never sees protected characteristics. If the optional Gemini key is set, PDFs with readable text are sent to Gemini as redacted text; photos and scanned PDFs have no text layer and are sent as images. The user's progress (skills, XP, badges) is kept only in their own browser's local storage. The API key is stored in Replit Secrets, never in the repository. Our demo uses synthetic CVs only.

6.2 Known Limitations & Risks [max 150 words]

Bias and scope: Model 1's labels describe US jobs in 2023; we apply them to Malaysia and use Malaysian job-market data alongside. Accuracy: Model 1 is 73.4% accurate on unseen occupations and weakest on "chatbot-only" tasks; Model 2 uses research papers as a proxy for AI capability and cannot foresee sudden breakthroughs; Catch the AI is one short exercise. Hallucination: mitigated by design – no generative model writes recommendations, and Gemini's CV phrases are rejected unless found in the CV text. Provider dependency: Gemini is optional with an offline fallback; if an arXiv refresh fails, the last good snapshot is kept. Mitigations shown to users: two scenarios, low–high ranges, a plain-English reason for every number, and a clear message that results are estimates and never hiring decisions.
